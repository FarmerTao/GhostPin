# 手机操作与排障

[English](workflow.md) | [简体中文](workflow.zh-CN.md)

## 1. 准备环境

使用实际连接手机的 Mac 上的终端。纯浏览器或云端 agent 没有本机执行工具时，无法访问 USB 手机。仓库脚本仅支持 macOS，不应把 Windows/Linux 说成已验证等价路径。

`scripts/bootstrap.sh` 在 skill 目录创建 `.venv`，安装 `scripts/requirements.txt` 固定的顶层依赖。需要已有 Python 3.12+；若 `python3` 指向 Apple 较旧的命令行工具版本，用 `PYTHON_BIN` 指定新版解释器。不要覆盖 `HOME`、`CODEX_HOME`、系统 Python 或全局 pip 包。

虚拟环境、`.cache` 下载和 `.state` 锁文件留在本机并被 Git 忽略。上游也可能使用 `~/.pymobiledevice3` 缓存支持文件和配对信息。不要为了清理而删除整个目录，它可能被其他工具共享。网络较慢时安装可能持续数分钟，应检查实际进度并提供有意义的更新。

## 2. 连接和信任

引导用户：

1. 用支持数据传输的线直接连接手机。显示充电不代表数据连接成功。
2. 解锁手机。Mac 如提示允许配件连接，允许本次连接的 iPhone。
3. 在手机点击“信任此电脑”，并在手机上输入密码。
4. 保持连接。Finder 可辅助确认，但以 `location.py devices` 获取设备列表。

`devices` 使用简化 USB 枚举，配对未完成也可能列出手机。因此后续 `doctor` 失败可能是信任尚未确认。连接多台设备时不得默认选第一台。确定目标后，所有操作及重启后都复用同一个 `--udid`。

## 3. 显示并开启开发者模式

运行 `doctor --udid ID`。若 `developer_mode` 为 false，引导用户到“设置 → 隐私与安全性 → 开发者模式”。入口缺失时运行 `reveal --udid ID`，再让用户退出并重新打开设置。

`reveal` 只发送显示入口请求，不证明入口已经可见或模式已经开启。由用户打开开关、接受重启、重启后解锁并确认“开启”。重新运行 `doctor`，仍为 false 时不能继续。不要用上游自动开启命令跳过用户重启和确认步骤。

Agent 提示示例：

> 已请求显示开发者模式入口。请重新打开“设置 → 隐私与安全性”，开启开发者模式，按提示重启，解锁后再次确认“开启”。完成后告诉我。

## 4. 挂载开发者支持文件

保持手机解锁，运行 `prepare --udid ID`。它检查版本、开发者模式和 Personalized 镜像是否已挂载；若未挂载，调用上游 `mounter auto-mount`，最多等待 180 秒，之后独立检查挂载列表。USB 或网络访问可能需要宿主授权，应使用 agent 的正常权限流程。

个性化签名步骤会连接 Apple。文件下载完成不等于对所有机型都能成功挂载。遇到 build identity、签名、不支持的服务或更新的 iOS，需检查当前上游支持情况，不要盲试镜像或修改设备安全设置。

### 下载备用路径

原始会话连接 `raw.githubusercontent.com` 超时，但 `api.github.com` 可访问。`fetch_ddi.py` 会：

1. 将上游 `doronz88/DeveloperDiskImage` 的 ref 解析为固定 commit。
2. 从该 commit 读取 Personalized 镜像、trust cache 和 build manifest 的元数据。
3. 通过 GitHub API 下载 blob，并设置网络超时。
4. 校验长度与 Git blob SHA-1，在本地记录 SHA-256 和 commit，生成完成清单。

下载脚本成功后再执行 `prepare --ddi-dir PATH`。准备脚本会对照完成清单检查文件；清单并非独立信任根，只应从预设上游获取文件。镜像是外部运行资源，不要提交到仓库。

遇到 API 限流或连接错误，解决原因后再试，不要无限重试。此工具不需要 GitHub token，不要要求用户在聊天中提供 token 来绕过限流。默认 `main` 可能变化；可用 `--ref COMMIT` 重现已记录版本。升级运行时后不要悄悄替换其期望的镜像版本。

## 5. 选择位置并保持会话

明确地点及坐标系。用户只说“复旦”时应确认校区；已经说明“邯郸”则保留该目标。需要精确定位时选具体地标或地址，不要仅凭城市猜坐标。

`set` 接受有限的经纬度，并强制指定 `--source wgs84` 或 `--source gcj02`。GCJ-02 转换采用大陆坐标常见近似算法，不具备测绘精度。BD-09 或未知坐标需另行确认来源和转换，不要直接当 WGS84。注意参数顺序是纬度、经度。[复旦示例](fudan-example.zh-CN.md) 记录了输入与转换值。

使用可持续运行的终端或 PTY。Helper 在子会话运行上游并等待；同一设备在本 skill 中只能有一个持锁的 `set` 会话。上游显示“Press Ctrl+C…”表示设置调用后进入等待。Wrapper 起初输出“Requesting…”仅代表准备请求，不能当作成功证据。隧道或连接仍报错时不能宣称完成。

固定的上游版本会对 iOS 17+ 自动尝试 macOS 原生隧道。“retrying over native tunnel”本身不是失败。不要提前启动 sudo 隧道、终止 Apple 服务或改全局网络。自动连接失败时，依据具体错误查阅[上游隧道说明](https://doronz88.github.io/pymobiledevice3/guides/ios17-tunnels/)。

## 6. 分别验证

让用户：

1. 打开地图，点击“当前位置”，确认蓝色位置标记，而非搜索结果图钉。
2. 退出并重新进入目标 App 或小程序，必要时授权定位并触发新读取。
3. 分别报告地图与目标应用结果，以及看到的错误。

地图位置正确与目标应用接受位置是两项不同事实。应用可能缓存位置、使用其他信号或识别软件模拟。Apple 提供 [`isSimulatedBySoftware`](https://developer.apple.com/documentation/corelocation/cllocationsourceinformation/issimulatedbysoftware) 标记。应用拒绝时如实报告，不扩展到规避检测。注册或其他业务提交由用户处理。

## 7. 恢复并结束

- 首选：向确切的 `location.py set` 会话发送 Ctrl+C。Helper 通过当前子进程句柄停止它，再对同一 UDID 执行 `clear`。
- 会话不存在或被强制结束：重新连接、解锁原设备，运行 `clear --udid ID`。
- 在另一终端清除：原 `set` 可能仍在等待，但不会持续重发位置。开始新会话前退出旧会话；不要混用多个 wrapper 和上游直连会话。
- 检查返回结果。失败或超时应明确说“恢复未确认”，不能把终止进程或拔线视为恢复成功。
- 到地图验证当前位置。若显示缓存位置，重开地图；常规恢复不可用时，可由用户重启手机再验证，不保证重启消除所有 App 缓存。
- 开发者模式仍会保持开启。用完可由用户在设置中关闭，并按提示重启；这属于可选清理，`clear` 不会自动关闭。

## 排障

| 现象 | 下一步 |
|---|---|
| Python 是 3.9 / 安装拒绝版本 | 通过 `PYTHON_BIN` 选择已有 Python 3.12+，不改系统 Python。 |
| 没有 USB 设备 / 只能充电 | 解锁、重连，检查数据线、接口及配件权限。 |
| 多台 USB 设备 | 确认目标 ID，全流程指定 `--udid`。 |
| 等待信任/配对 | 由用户在手机确认，不索取密码。 |
| usbmux 报 `Operation not permitted` | 走宿主 USB/沙箱授权流程；不同于手机信任。 |
| 找不到开发者模式 | `reveal` 后重开设置，再由用户开启、重启、确认。 |
| 准备时 `DeviceLocked` | 等用户解锁并保持亮屏，确认后重试一次。 |
| Raw GitHub 下载卡住 | 停止该尝试，使用 API 下载脚本和 `--ddi-dir`。 |
| API 403/429 | 检查限流或网络原因，稍后重试；不循环、不编造镜像源。 |
| 不支持的 build/签名/服务 | 核对最新上游支持情况，不声称所有 iOS 17–26 都可用。 |
| 原生隧道重试警告 | 等正常回退完成，检查最终结果。 |
| 地图偏移数百米 | 检查坐标系及经纬度顺序。 |
| 地图正确，小程序不变/拒绝 | 区分结果，重开并重新请求定位一次，不保证接受。 |
| 断线后恢复失败 | 重连并解锁同一设备、clear、验证；不可用时考虑用户重启。 |

同样错误在没有状态变化的情况下重复出现，应停止依赖操作，说明缺少的手机操作或外部阻碍，不要隐藏仍在等待的进程。
